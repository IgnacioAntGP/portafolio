Decisiones de Arquitectura

El backend está estructurado bajo una arquitectura de capas desacoplada, asegurando que cada componente posea una única responsabilidad bien definida:

  • Capa Dual de Controladores: Separación estricta entre controladores MVC (@Controller) para renderizado de vistas con Thymeleaf y controladores API (@RestController) para intercambio de datos en formato JSON.
  • Lógica de Negocio y Servicios: Capa de servicios (@Service) con inyección de dependencias por constructor e inmutabilidad con campos private final, encapsulando reglas del negocio y validaciones.
  • Persistencia y ORM: Implementación de Spring Data JPA con (JpaRepository), eliminando SQL manual redundante y garantizando transaccionalidad.

Seguridad y Defensa (Spring Security)

Implementación de un modelo de defensa en profundidad centralizado a través de la cadena de filtros nativa (SecurityFilterChain):

  • Autenticación: Integración de UserDetailsService personalizado para validar credenciales dinámicas en base de datos comparando hashes criptográficos generados con BCryptPasswordEncoder.
  • Control de Acceso Basado en Roles:
    • ROLE_ADMIN: Acceso a CRUD completo de Gestión de los Estudiantes.
    • ROLE_USER: Acceso de lectura al catálogo general y redirección a su panel exclusivo del bootcamp.
  • Protección de la API REST: Activación de autenticación HTTP Basic en rutas /api/** y exclusión selectiva de CSRF únicamente para clientes HTTP no navegadores (Postman).

Interoperabilidad & API REST

Para desacoplar el modelo relacional del transporte de datos, la API REST implementa un formato de mensajería uniforme:

ApiResponse<T>

Todas las respuestas HTTP viajan dentro de un envoltorio estándar que unifica metadatos: 

{
    "success": true,
    "message": "Operación exitosa",
    "results": 1,
    "version": "1.0",
    "data": { ... }
}
